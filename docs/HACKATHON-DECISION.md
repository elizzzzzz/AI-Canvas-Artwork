# 1024 Hackathon 交付决策

## 决策时间

2026-10-25 19:00（Asia/Shanghai）。

## 规则依据

附件《2026 1024 Hackathon 启动&规则介绍.pdf》规定：

- 开发及作品提交截止：**2026-10-26 09:00**；届时仓库不允许继续出现修改痕迹。
- GitHub 必须包含全部源代码、运行说明、架构设计文档（模块规格、分工）和录制的 Demo 视频。
- 每次变更应通过 Pull Request，仓库要保留开发过程；使用既有 codebase 时应在团队新增代码前创建 `v0` tag。
- 研发赛道评分为：商业价值与产品设计 50%、架构设计 20%、AI 价值呈现 15%、AI 工程效率 15%。
- PDF 没有规定 Demo 视频的时长、分辨率、画幅或编码，也没有明确规定必须提交 PPT；本项目仍制作 PPT 作为路演辅助材料。

附件是比赛材料，提供评审要求和截止时间；项目内强制 3D 生产规则继续约束实际媒体生成。

## 当前事实

- 动作时长比例：56.00% / 65.16% / 69.09%。

- 已生成的 8 张图片仍是概念候选；没有经 3D 逐镜头批准的完整 AI 视频成片。

## 19:00 决策

今晚交付包采用“灰模 Demo + 工程过程 + 汇报 PPT”路径：

1. 以 12 段逐帧 3D 灰模证据组装一条竖屏 Demo 视频，明确标注 `GRAYBOX REVIEW / NOT FINAL MEDIA`。
2. 以比赛评分维度制作深色海军蓝、荧光绿色视觉风格的汇报 PPT，重点展示业务价值、AI 工程流程、架构、资产库、3D 门和可复现证据。
3. 保留 GitHub PR 过程、运行说明、架构文档、README 数据看板和过程日志。
4. 不运行图片或视频生成，不把内容审核通过写成生成批准，不伪造最终成片状态。

这样可以在今晚形成可运行、可审阅和可复现的完整 Demo 交付。最终 AI 渲染片仍需在逐段 3D 运动审核和人工签核完成后再生成。
