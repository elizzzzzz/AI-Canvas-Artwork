# 强制 3D 制作前置规范

2026-10-24，用户明确要求：所有场景先通过 3D 建模确认比例、遮挡、人物位置和朝向，以及道具—人物—场景关系；3D 是所有画面及视频运镜生产前的必选项。本项目将“任务位置”按人物位置落实，同时验证主任务与支线动作的空间因果。

这条要求替代过去“先出参考图、再补灰模”的安排，立即适用于尚未执行的 P01 修图和视频试跑，不追溯重跑已完成素材。

## 适用范围与门槛

| 范围 | 必须先具备的 3D 依据 |
|---|---|
| 角色参考照 | 有尺度的身体、头部、手部体块/骨架、体态与服装轮廓；对应参考照相机。脸部纹理风格不是几何审批的替代品 |
| 场景空景 | 真实三维建筑、门洞、桌柜、道路、车厢等空间，正确人眼高度和镜头；空景不混入未登记人物 |
| 道具图与编辑图 | 真实比例、厚度、内腔、支撑、接触和运动机构；保留周边物体，不能只验证孤立道具 |
| 每张叙事画面/关键帧 | 对应场景、全部可见人物、道具、遮挡、朝向、动作状态和相机；只能显示主人公当下可感知的信息 |
| 每段视频及运镜 | 同上，加完整时序中的相机与人物/道具轨迹、关节、支撑和接触，逐目标帧检查，不能只看首尾帧 |
| 重抽、修图和更换参考 | 同样检查，不因“小修”免除 3D；先确认旧包仍有效，发生结构变化则重建对应包 |

概念图只用于美术方向，不能作为 3D 包的替代。可复用同一场景模型，但每个画面/片段必须引用已审核的具体模型版本、姿态、道具状态和摄影机。

## 坐标、比例与实体

统一右手坐标系、米为长度单位、+Z 向上、每个实体局部 +Y 为朝前，角度单位 degree。导入 P01 旧灰模时由 cm 显式乘 0.01；不通过隐式缩放拼场景。当前工程尺寸是设计设定，不称作实测或历史事实。

每个实体记录唯一 ID、模型来源、版本、尺寸包围盒、4×4 变换或等价的位置/旋转/缩放、支撑物 ID、父子关系及运动轨迹。人物额外记录身高、眼高、肩宽、骨架/姿态、头部与视线朝向；手持道具记录握持点和手骨关系。台面、地面、车辆、马、门洞、灯具也必须有实体与尺度。

开启道具要有真实机构：P01 的同一块刚性盖板绕箱体后沿固定轴转动，合页同轴、内腔与厚度成立。接触、穿插和支撑关系区分：握持处的合法接触不作为误穿模，其他位置仍要检查。没有依据的悬浮、盖板平移代替旋转和物体凭空复制均阻塞。

## 每个范围的 3D 交付包

所有路径相对仓库根目录、使用 SHA-256 固定内容；大型证据也必须有可取得的本地文件或项目内清晰的导出路径，不能只放失效外链。

| 证据键 | 具体内容 |
|---|---|
| `model` | 可编辑/可交换三维模型，含足够的身体、手部和道具结构；OBJ/glTF/GLB/Blender 等按实际工具保存 |
| `scene` | 实体清单、坐标单位、变换、比例、关节、父子关系、接触/支撑、关键任务动作与时间轴 |
| `camera` | 主观主人公、眼位、焦距/传感器或视场角、画幅、俯仰、裁切、近远裁面及完整相机路径 |
| `preview` | 主观灰模图/动态预演；同时附顶/侧/透视诊断图或可查看的预演包，显示遮挡与方向 |
| `depth` | 同一相机对应的深度证据；视频逐帧或可索引序列，不能拿另一机位代替 |
| `object_ids` | 物体 ID/分割证据与关键物体标签，便于核对是否看见正确物件及被谁遮挡 |
| `report` | 实际检查结果、证据文件哈希、当前范围和版本、逐帧检查，以及人工签核 |

模型、相机、预览、深度和 ID 图必须来自同一版本的场景。布景诊断图允许第三人称，只能作为制作参考；成片摄影继续全镜头第一人称。

## 检查项目

基础项：尺度/单位、实体变换、人物与视线朝向、关节/铰链限制、接触和支撑、非预期穿插、关键物件可见性与遮挡、安全区构图、主观机位、道具状态连续性。

关键证据、手、口型必须有明确屏幕包围盒/可见比例与遮挡者记录；阈值按镜头指定，不能用一个统一比例掩盖特写与远景差异。口播中镜头前人员与镜后主人公同处现场，镜头前口型无遮挡。角色首次登场慢动作也要检查中间姿态与时长。

视频再查：相机净空、完整运镜、时间连续性、全帧覆盖。当前分段预演采用 24fps，检查每帧及结尾边界；手触铜扣、盖板旋转、车轮接地、交接物件等关键运动增加检查采样或连续约束，避免只在相邻帧之间穿越。最终如果用其他帧率、速度变化、裁切或插帧，更新摄影机包并重新验收，不能只沿用 24fps 报告。

## 放行与失效

1. 每个范围先完成模型及证据；当前清单中未知的实体、尺寸与姿态必须补全，不能把空值填为“通过”。
2. 制作者实查几何和动态预演，修复结构、朝向、遮挡与接触问题；实际报告记录失败与修复，不由自动脚本凭空生成。
3. 由明确的评审人批准当前版本，记录审批时间、源码哈希和证据哈希。
4. 提交生成前运行 `python3 tools/geometry_preflight.py --scope <范围>`，必须返回 0，再同时满足艺术审核与当次费用范围。
5. 按通过的灰模提供构图/深度/关键帧约束，生成后逐图、逐段对照检查，发生偏离仍退回修复。

改模型、比例、人物或道具变换、姿态、朝向、机构、相机、运动时间或依赖提示词，受影响的批准立即失效。当前预检采用保守策略，任一资产定义变化会使相关源哈希不匹配；重新确认影响范围后再做版本化更新。

预检程序只校验覆盖、证据是否存在/被修改、版本/源码是否匹配、人工记录与完整帧检查字段；**它不是碰撞求解器、图像几何检测器或自动艺术审批器**。Canvas 布尔条件提供实际运行阻断，也不能代替三维检查。所有原生运行、API、重试与修图入口均必须遵守相同规则。
